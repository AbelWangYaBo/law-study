# GMP 内容、检查指导原则与标准地图 设计

日期：2026-11-25　|　状态：设计已逐节确认，待复核本文档　|　上游：[系统设计](../../design.md)

## 目标

把医疗器械、药品两个行业的生产质量管理规范（GMP）做进法规学习系统，并让国家标准成为理解、学习和在工作中应用 GMP 的抓手：

1. **GMP 全套入库**：现行/最新版正文与附录逐条生成 AI 解读和场景分析；被替代的旧版全文入库备查。
2. **检查指导原则可浏览**：2026 版医疗器械 GMP 检查指导原则导入系统，按条款互链，读 GMP 条文时能看到「现场检查怎么查」。
3. **标准地图**：调研与 GMP 相关的国家标准、行业标准，融进每条解读，并在系统里提供按 GMP 章节浏览、可跳转的「标准地图」页面，同步产出文档、更新法规总表的标准卡。

版本是这件事的第一风险：两部 GMP 及其附录在 2025—2026 年都有更新，法规总表里部分文件标注的「现行有效」已经过时。

## 范围

**包含**

- 医疗器械 GMP：2025 年第 107 号版正文、无菌/植入性/体外诊断试剂/定制式义齿/独立软件 5 个附录；2014 年版作为旧版备查。
- 药品 GMP：2010 年修订版正文、全部附录（以调研核实的现行版本为准）；有新旧两版的，旧版备查。
- 医疗器械 GMP 检查指导原则（2026 版通用版 + 5 个专项）。
- 与 GMP 相关的国家标准、行业标准、国家计量技术规范、药典的调研与地图。

**不包含**

- 经营质量管理规范（GSP）、临床试验质量管理规范（GCP）、药物非临床研究质量管理规范（GLP）。
- 药品 GMP 的检查指南；医疗器械 GMP 检查指导原则的旧版（2015 年版等）。
- 标准全文入库（标准文本受版权保护，只做信息卡与用途说明）。
- 不建数据库表承载检查项和标准，不做三者的图谱。

## 总体方案与阶段

| 阶段 | 内容 | 结束条件 |
|---|---|---|
| 0 调研 | 版本核对、补抓缺失全文、检查指导原则结构确认、标准调研 | **版本清单经用户确认** |
| 1 内容 | 最新版入库（含旧版备查）、解析器扩展、选择器分组、逐条解读 | 校验通过 → 提交推送 |
| 2 页面 | 检查指导原则页、标准地图页、互链、标准地图文档、法规总表标准卡 | 浏览器实测通过 → 提交推送 |

新数据用静态 JSON：检查项和标准都是只读内容，由脚本生成为 `web/public/data/*.json` 随构建产物发布。本地动态模式和 Pages 快照模式读取同一份文件，不需要新增表和接口。

## 一、调研与版本核对（阶段 0）

**要回答的问题**

- 每个文件的现行版本、发布文号、施行日期；有无已发布未施行的版本、有无征求意见稿（如 2026-09 的中药饮片附录征求意见稿）。
- 已知线索：药品 GMP 药用辅料附录、药包材附录（2025 年第 1 号公告，2026-01-01 施行）；无菌药品附录有 2026 年修订版；器械 GMP 2025 年版 2026-11-01 施行，药监局通知要求五类产品同时符合新规范和各自现行附录。
- 每个文件对应哪份检查指导原则，检查项里的「《规范》条款」「《附录》条款」如何引用。

**做法**

- 每部法规一个调研代理，用官方来源（国家药监局、卫生部/国家卫健委、中国政府网）核实；事实带来源，未核实的明确标注。
- 缺失或过时的全文从官方来源补抓进法规总表，沿用现有 md 格式（YAML 元数据 + 正文），入库前与官方原文逐段比对。
- 标准调研：以 GMP 各章为主线，列出支撑每章要求的标准，核实现行状态与替代关系，写明用途、产出记录和获取渠道。法规总表已有的 62 张标准卡逐张复核（已知 YY/T 0287-2017 的「现行有效」存疑）。

**产出**

- 版本清单（`docs/gmp-versions.md`）：文件名、版本、文号、施行日期、现行/旧版、新旧对应、来源链接。**交用户确认后才进入阶段 1**，随阶段 1 提交入仓库。
- 各文档的调研简报与标准简报（`data/gmp-drafts/`，不入库），供撰写解读的代理使用。

## 二、内容入库（阶段 1）

**命名**（`Law.name` 唯一，以此为准）

| 类别 | 命名 | 解读 |
|---|---|---|
| 现行器械 GMP | `医疗器械生产质量管理规范` | 逐条 |
| 器械 GMP 附录 | `医疗器械生产质量管理规范附录 无菌医疗器械` 等 | 逐条 |
| 旧版 | `医疗器械生产质量管理规范（2014年版，已被替代）` | 不生成 |
| 药品 GMP 正文 | `药品生产质量管理规范（2010年修订）` | 逐条 |
| 药品 GMP 附录 | `药品生产质量管理规范附录：无菌药品` 等 | 逐条 |
| 附录旧版 | `药品生产质量管理规范附录：无菌药品（2011年版，已被替代）` | 不生成 |

旧版的效力层级写「历史版本」，在界面上与现行版明确区分。最终清单以阶段 0 的版本清单为准。

**解析器扩展**（`app/importer/parsers.py`）

- 现有规则：行首「第X条」切条，章/节标题跳过。
- 新增：全文没有「第X条」时，按「数字.数字」编号切条（如独立软件附录的 `1.1`、`1.2`），编号作为条款名；「第X部分」按标题跳过。
- 入库走现有 `scripts/import_law.py`，重复导入是原位更新，法规/条款/段落 ID 稳定。

**界面**

- 法规选择器按三组显示：法律法规 / 质量管理规范 / 历史版本。分组由法规名和效力层级推导，不新增字段。
- 快照模式下，整部法规没有任何解读时，阅读页不显示「AI 解读 / 场景分析」按钮（旧版备查用）。

## 三、解读模板（阶段 1）

只对现行/最新版生成，每条两份，沿用现有两阶段流程（调研简报 → 撰写），并发不超过 4 个代理。在现有结构上为 GMP 增加小节：

**AI 解读**

| 小节 | 内容 |
|---|---|
| 本条要点 | 这条规定了什么 |
| 关键角色与义务 | 义务主体与义务，表格 |
| 白话解读 | 通俗解释，点出限定词和易错处 |
| **新旧对照** | 有旧版时必写：新增 / 改写 / 沿用，注明旧版条号；没有旧版则不写此节 |
| 记忆锚点 | 按条文行文串联关键词、并列项口诀、与相邻条文对比 |

**场景分析**

| 小节 | 内容 |
|---|---|
| 落地场景 | 血管介入支架类产品企业在注册、生产、检验、放行、上市后各环节落到什么动作 |
| 对产品经理意味着什么 | 日常哪里遇到，要产出什么文件/记录/流程 |
| **现场检查怎么查** | 器械类必写：对应检查指导原则的条款号、风险等级、检查内容摘要 |
| **相关标准** | 支撑本条的标准：标准号、用在哪一步、产出什么记录；只写调研简报里核实过的 |
| 风险提示 | 不符合的后果，结合检查/飞检场景 |

药品 GMP 的场景分析把「落地场景」写成药品场景，并增加一节 **与器械 GMP 的对照**（对应器械 GMP 哪一条，或说明器械没有对应要求）；不写「现场检查怎么查」。

规则与现有 9 部一致：忠于条文，条文之外的事实须有来源，不出现真实公司名，纯 markdown，篇幅与条文信息量匹配。先出一份试点批次，抽检合格后再批量。

## 四、检查指导原则（阶段 2）

**数据**

法规总表里的 6 份检查指导原则是六列表格：

| 章节 | 序号 | 条款 | 内容 | 风险等级 | 《规范》条款 |
|---|---|---|---|---|---|
| 第一章总则 | 1 | 1.1.1 | 企业应当… | *** | 《规范》第三条 |

`scripts/build_inspection.py` 读取这些 md，生成 `web/public/data/inspection.json`：

```
{
  docs: [{
    id, name, doc_number, effective_date, scope,        // 通用 / 无菌 / 植入性 / 体外诊断试剂 / 定制式义齿 / 独立软件
    gmp_law, appendix_law,                               // 对应的法规名（appendix_law 可为空）
    source,                                              // 官方链接
    items: [{ no, clause, chapter, content, level,       // level: 关键 / 主要 / 一般
              refs: [{ target: "gmp" | "appendix", articles: [3, 4] }], refs_raw }]
  }]
}
```

解析规则：

- 章节列为空的行沿用上一行的章节；`<br>` 换成空格；章节名规范成「第一章 总则」。
- 风险等级按星号数映射：`***` 关键、`**` 主要、`*` 一般。
- 条款列解析成 `refs`：带《规范》《附录》前缀的按前缀归入；不带前缀的沿用同格内最近的 target；「第十条至第十二条」展开为 10、11、12；解析不了的保留 `refs_raw`，脚本输出清单，必须人工过目。
- 文档的文号、施行日期、官方链接取自 md 的 YAML 元数据；scope 与法规名的对应写在脚本常量里。

**页面** `/inspect`

- 顶部切换 6 份文档；按章节、风险等级、关键词筛选。
- 每项显示条款号、风险等级、检查内容，以及对应的 GMP/附录条款，点击跳到阅读页对应条款。
- 支持 `?law=<法规ID>&article=<条号>` 进入时按该条款筛选全部文档。

## 五、标准地图（阶段 2）

**数据**：`web/public/data/standards.json`，由调研结果整理而成，是页面和文档的唯一数据源。

```
{
  chapters: [{ law, title, articles: [范围] }],          // GMP 章 → 条款范围，用于分组和跳转
  standards: [{
    number, name, kind,                                   // 推荐性国家标准 / 强制性国家标准 / 行业标准 / 指导性技术文件…
    status, effective_date, replaces,                     // 现行 / 即将实施 / 已废止；被替代的标准
    international,                                        // 对应的国际标准及采标关系
    themes,                                               // 主题标签，如 灭菌确认、洁净室、软件生存周期
    gmp: [{ law, chapters, articles }],                   // 支撑哪部 GMP 的哪些章/条
    usage, outputs,                                       // 用在哪一步、产出什么记录
    access, url                                           // 获取渠道与官方页面
  }]
}
```

**页面** `/standards`

- 按 GMP 章节分组展示，可切换器械 GMP / 药品 GMP，可按标准号、名称、主题搜索。
- 每项显示标准号、名称、类型、状态、替代关系、国际标准、用途；可跳到对应的 GMP 条款。
- 支持 `?law=<法规ID>&article=<条号>` 进入时只列与该条款相关的标准。

**文档与知识库**

- `scripts/build_standards_doc.py` 由同一份 JSON 渲染 `docs/gmp-standards-map.md`，保证页面与文档一致。
- 法规总表 `14_标准_国标行标/`：补全缺失的标准卡、更正过时状态，沿用现有卡片格式；改动前原件备份到 `data/source-backup-<日期>/`。标准地图文档的副本放进法规总表。

## 六、前端改动汇总

- 新增路由与导航：`/inspect` 检查指导原则、`/standards` 标准地图。
- 新增两个视图；静态数据用相对路径 `data/*.json` 读取，与现有 `api-snapshot/` 的读取方式一致。
- 阅读页：每条条款加锚点；条款标题旁显示「检查项 N」「相关标准 N」，点击跳到对应页面并按该条筛选。法规与 JSON 的对应靠法规名，运行时由法规列表解析成 ID。
- 跳转到阅读页：切换当前法规、回到阅读页、滚动到条款锚点。

## 七、测试与验收

**自动化（pytest）**

- 解析器：「数字.数字」切条、「第X部分」跳过、有「第X条」时不受影响。
- `build_inspection.py`：用内嵌的表格样例覆盖章节补全、星号映射、条款引用解析（含区间、无前缀、不可解析）。
- `build_standards_doc.py`：由样例 JSON 渲染出预期的章节与条目。
- 原有测试全部通过。

**内容**

- 所有入库法规与源文件逐条逐段一字不差；每条现行版条款恰好一份解读和一份场景分析。
- 解读结构校验、敏感信息扫描、罚则与标准号的抽检。
- 版本清单里每个文件都有可追溯的官方来源。

**界面**（构建通过后，本地动态模式和静态预览各测一遍）

- 选择器三组显示正确；旧版在快照模式下不显示解读按钮。
- 阅读页的「检查项 N」「相关标准 N」数量正确，跳转后筛选结果正确。
- 检查指导原则页、标准地图页的筛选、搜索、跳转正常。

**发布**：每阶段提交推送，Pages 部署成功后核对线上数据。

## 八、风险与对策

| 风险 | 对策 |
|---|---|
| 版本判断错误，导致上千份解读基于错误文本 | 版本清单经用户确认后才进入阶段 1；入库前逐段比对官方原文 |
| 旧版全文、部分附录在官网已下架或只有附件 | 从官方转载页、地方局转载获取，注明来源；确实取不到的在清单里标明，不猜测内容 |
| 标准全文多不免费（行标尤其） | 只做信息卡与用途说明，状态和替代关系以国家标准全文公开系统等官方渠道核实 |
| 国家药监局网站有反爬，附件下载受限 | 沿用之前沉淀的办法（附件直链、浏览器取链接），取不到的记入清单 |
| 账户速率限制 | 子代理并发不超过 4，分阶段进行 |
| 工作量大（解读约 2000 份） | 分阶段推送；试点批次先行；每阶段结束可独立交付 |
